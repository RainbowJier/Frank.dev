> **适合人群**：写过 MySQL、第一次接触 Oracle 的同学。已有的 SQL 知识能复用八成，这篇文章帮你把剩下两成的"概念弯"拐过来。
> 本文以 Oracle 23ai（Free 版）为准，所有代码都能在 Docker 里直接跑。

## 一、Oracle 是个啥？为啥要学？

一句话定位：**MySQL 是互联网的国民数据库，Oracle 是传统行业的老钱数据库**。银行核心系统、保险、电信计费、政务、大型 ERP，背后大概率是 Oracle——你在公司接手一个"祖传系统"，八成就是它。

和 MySQL 比，Oracle 有三个明显特点：

- **功能重**：分区、闪回、RAC 集群、并行查询都是原生能力，代价是概念多、上手陡
- **商用收费**：企业版按 CPU 授权，价格不便宜；但官方提供免费的 Free 版（限 2 核 2GB 内存、12GB 用户数据），学习完全够用
- **版本演进**：8i/9i 互联网时代 → 10g/11g 网格 → 12c 引入云架构（CDB/PDB）→ 19c（当前企业主流 LTS）→ 23ai（支持 AI/JSON/开发友好语法）

好消息是：**SELECT、JOIN、GROUP BY 这些你都会，直接用**。要重新理解的是"库"这个词——Oracle 里的"数据库"和 MySQL 里的"数据库"根本不是一回事。下面逐个讲清。

## 二、先跑起来：Docker 三分钟

学习环境用社区维护的 `gvenzl/oracle-free` 镜像（内置 Oracle 23ai Free）：

```bash
docker run -d --name oracle-free \
  -p 1521:1521 \
  -e ORACLE_PASSWORD=Test_1234 \
  gvenzl/oracle-free:23-slim-faststart

# 首次初始化要等一两分钟，看到 "DATABASE IS READY TO USE!" 即可
docker logs -f oracle-free
```

进入 SQL*Plus 命令行：

```bash
docker exec -it oracle-free sqlplus system/Test_1234@localhost/FREEPDB1
```

`FREEPDB1` 是默认的可插拔数据库（PDB）的服务名。12c 之后 Oracle 分成了**容器库（CDB）+ 可插拔库（PDB）**两层：CDB 是底盘，PDB 是插上去的业务库，日常操作都在 PDB 里。现在只需要记住：**连接串最后一段写 `FREEPDB1`**。

连上后先跑两条"开机验证"：

```sql
SELECT instance_name, status FROM v$instance;  -- 状态应为 OPEN
SELECT name FROM v$database;                    -- 库名 FREE
```

图形工具可以用官方的 SQL Developer，或者浏览器访问 Database Actions（`http://localhost:8080`）。

## 三、概念差异一：实例 ≠ 数据库

这是 MySQL 用户转 Oracle 的第一个认知冲击。

在 MySQL 里，一个 `mysqld` 进程 + 一堆 `.ibd` 表文件，我们随口说的"数据库"其实指两者合起来。Oracle 把这两件事**严格拆开**：

- **实例（Instance）**：内存 + 后台进程，是"活着的"运行态。核心是一大块共享内存 **SGA**（System Global Area，含共享池、数据缓冲区、日志缓冲），再加一群各司其职的后台进程（DBWn 写数据块、LGWR 写日志、CKPT 做检查点、SMON/PMON 做恢复清理）
- **数据库（Database）**：磁盘上的文件集合，是"静止的"。三类关键文件：数据文件（`.dbf`）、控制文件（记录库结构）、联机重做日志（Redo Log）

平时说的"Oracle Server" = 实例 + 数据库。启动过程就是把两者关联起来：NOMOUNT（只起实例）→ MOUNT（读到控制文件）→ OPEN（打开数据文件），每一步能查的东西都不同——这也是面试常问点。

![图1：Oracle 实例与数据库的关系](/images/svg/oracle-instance-architecture.svg)

**为什么这样设计？** 最直接的好处是 RAC（Real Application Clusters）：多台机器各跑一个实例，**同时打开同一个数据库**，对外像一个库一样提供服务——这是 MySQL 主从方案给不了的共享存储架构（MySQL 8 之后官方推荐的 InnoDB Cluster 也还是主从路线）。

日常对照：

| 你熟悉的 MySQL | Oracle 里对应 |
| --- | --- |
| `SHOW DATABASES;` | `SELECT name FROM v$database;` |
| `SHOW PROCESSLIST;` | `SELECT sid, username FROM v$session;` |
| `systemctl restart mysql` | `SHUTDOWN IMMEDIATE; STARTUP;` |

## 四、概念差异二：表空间与存储层级

MySQL 里"库是目录、表是 `.ibd` 文件"，逻辑和物理一一对应。Oracle 在中间加了一层抽象：**表空间（Tablespace）**。

建表时不指定文件，而是指定表空间；表空间再对应一个或多个 `.dbf` 数据文件。完整的层级是：

- **表空间**：逻辑容器，如 `USERS`、`SYSTEM`
- **段（Segment）**：一张表（或一个索引）对应一个段
- **区（Extent）**：一组连续的块，表扩容按区分配
- **块（Block）**：最小 I/O 单位，默认 8KB（MySQL 里对应的页是 16KB）

![图2：Oracle 逻辑存储层级](/images/svg/oracle-storage-hierarchy.svg)

看一眼系统自带的表空间：

```sql
SELECT tablespace_name FROM dba_tablespaces;
-- SYSTEM / SYSAUX / UNDOTBS1 / TEMP / USERS
```

五个默认表空间各司其职：

| 表空间 | 存什么 | 新手须知 |
| --- | --- | --- |
| `SYSTEM` | 数据字典（库自己的元数据） | **千万别放业务表**，放了 DBA 会找你谈话 |
| `SYSAUX` | 系统辅助数据 | 不用管 |
| `UNDOTBS1` | 回滚数据 | 事务回滚、一致性读靠它 |
| `TEMP` | 排序、临时表 | 大排序会往这里落盘 |
| `USERS` | 用户数据 | **业务表放这里** |

这个设计的好处是**逻辑与物理解耦**：表快满了，给表空间加一个数据文件就行，应用层无感；换块更快的盘，把文件搬过去即可。

## 五、概念差异三：用户就是 schema

MySQL 里你的世界是"库"：`USE mysql_zero_to_one` 之后建的表都属于这个库。Oracle 里没有 `USE`，世界围着**用户**转：

- 创建用户 `frank`，就自动存在一个同名 **schema**
- `frank` 登录后建的表，全名都是 `frank.表名`
- 访问别人的表，写全名 `scott.emp`；权限用 `GRANT` 控制

创建一个属于自己的工作空间：

```sql
-- 用 system 登录 FREEPDB1 执行
CREATE USER frank IDENTIFIED BY Pass_1234
  DEFAULT TABLESPACE users          -- 表默认放 USERS 表空间
  QUOTA UNLIMITED ON users;         -- 允许无限使用该表空间

GRANT CONNECT, RESOURCE TO frank;   -- CONNECT:能登录  RESOURCE:能建表
```

之后用 frank 重新连接：

```bash
docker exec -it oracle-free sqlplus frank/Pass_1234@localhost/FREEPDB1
```

![图3：MySQL 库与 Oracle schema 命名空间对照](/images/svg/oracle-mysql-schema-compare.svg)

对照着记：**MySQL 的"库" ≈ Oracle 的"用户/schema"**。所以 Oracle 的 `SHOW DATABASES` 对应的是 `SELECT username FROM all_users;`，而"这个库有哪些表"对应的是"这个 schema 有哪些表"（`user_tables`）。

## 六、建表实战：把电商例子搬到 Oracle

沿用 MySQL 系列的电商演示数据（users / products / orders），先看类型对照：

| MySQL | Oracle | 说明 |
| --- | --- | --- |
| `VARCHAR(n)` | `VARCHAR2(n CHAR)` | 注意 `CHAR` 后缀，否则按字节算，中文可能存不下 |
| `INT` / `BIGINT` | `NUMBER(10)` / `NUMBER(19)` | NUMBER 一个类型通吃整数和小数 |
| `DECIMAL(12,2)` | `NUMBER(12,2)` | 金额照旧精确存储 |
| `DATETIME` | `DATE` / `TIMESTAMP` | Oracle 的 DATE 自带时分秒 |
| `TEXT` | `CLOB` | 大文本 |
| `AUTO_INCREMENT` | `GENERATED AS IDENTITY` | 底层是序列（SEQUENCE） |
| 反引号 `` ` ` `` | 什么都不加 | 双引号有特殊含义，见后文"大小写坑" |

建表（用 frank 登录执行）：

```sql
CREATE TABLE users (
  user_id    NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  username   VARCHAR2(50 CHAR)  NOT NULL UNIQUE,
  email      VARCHAR2(120 CHAR) NOT NULL UNIQUE,
  status     NUMBER(1) DEFAULT 1 NOT NULL,
  created_at DATE DEFAULT SYSDATE NOT NULL
);

CREATE TABLE products (
  product_id   NUMBER(10) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  product_name VARCHAR2(120 CHAR) NOT NULL,
  price        NUMBER(12,2) NOT NULL CHECK (price >= 0),
  stock        NUMBER(9) DEFAULT 0 NOT NULL,
  created_at   DATE DEFAULT SYSDATE NOT NULL
);

CREATE TABLE orders (
  order_id   NUMBER(19) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id    NUMBER(10) NOT NULL,
  order_status VARCHAR2(20 CHAR) DEFAULT '待支付' NOT NULL,
  total_amount NUMBER(12,2) NOT NULL,
  created_at DATE DEFAULT SYSDATE NOT NULL,
  CONSTRAINT fk_orders_user FOREIGN KEY (user_id) REFERENCES users(user_id)
);

INSERT INTO products (product_name, price, stock) VALUES ('机械键盘', 399.00, 80);
INSERT INTO products (product_name, price, stock) VALUES ('USB-C 扩展坞', 269.00, 120);
INSERT INTO users (username, email) VALUES ('alice', 'alice@example.com');
INSERT INTO orders (user_id, order_status, total_amount) VALUES (1, '已支付', 668.00);

COMMIT;  -- Oracle 默认不自动提交，忘了 COMMIT 数据会"丢"
```

`GENERATED BY DEFAULT AS IDENTITY` 是 12c 之后的现代写法，老系统里更常见的是手动建序列：

```sql
-- 老写法：序列 + 手动取号
CREATE SEQUENCE seq_users START WITH 1 INCREMENT BY 1;
INSERT INTO users (user_id, username, email)
VALUES (seq_users.NEXTVAL, 'bob', 'bob@example.com');
```

## 七、高频差异语法速查

### 7.1 dual：没有 FROM 的查询

Oracle 要求 `SELECT` 必须有 `FROM`，查个当前时间也得"从某张表查"——官方提供了单行单列的虚表 `dual`：

```sql
SELECT SYSDATE FROM dual;          -- 当前时间
SELECT 1 + 1 FROM dual;            -- 当计算器用
-- 23c 起终于支持无 FROM：SELECT SYSDATE;
```

### 7.2 函数对照

| 干什么 | MySQL | Oracle |
| --- | --- | --- |
| 当前时间 | `NOW()` | `SYSDATE` / `SYSTIMESTAMP` |
| 字符串拼接 | `CONCAT(a, b)` | `a \|\| b`（双竖线） |
| 判空替换 | `IFNULL(x, y)` | `NVL(x, y)`（也支持 `COALESCE`） |
| 时间格式化 | `DATE_FORMAT(t, '%Y-%m-%d')` | `TO_CHAR(t, 'YYYY-MM-DD HH24:MI:SS')` |
| 字符串转日期 | `STR_TO_DATE(s, ...)` | `TO_DATE(s, 'YYYY-MM-DD')` |
| 截断小数 | `TRUNCATE(x, 2)` | `TRUNC(x, 2)` |

```sql
SELECT username || ' <' || email || '>' AS 联系方式 FROM users;
SELECT TO_CHAR(created_at, 'YYYY-MM-DD HH24:MI:SS') FROM orders;
```

### 7.3 取前 N 条与分页：ROWNUM

MySQL 的 `LIMIT`，Oracle 用 `FETCH` 对应（12c+）：

```sql
SELECT * FROM orders ORDER BY created_at DESC
FETCH FIRST 10 ROWS ONLY;          -- ≈ LIMIT 10
```

但老代码里满地都是 `ROWNUM`，它有个著名的坑：**`ROWNUM > 1` 永远查不到数据**。因为 ROWNUM 是"第几个被取出的行"：取第 1 行时编号 1，不满足 `> 1` 被丢弃；取第 2 行时它又成了编号 1……如此循环，全军覆没。

![图4：ROWNUM 分页原理](/images/svg/oracle-rownum-pagination.svg)

正确的分页写法是**子查询先编号、外层再取区间**：

```sql
-- 取第 11~20 条（≈ MySQL 的 LIMIT 10, 10）
SELECT * FROM (
  SELECT a.*, ROWNUM rn
  FROM (SELECT * FROM orders ORDER BY created_at DESC) a
  WHERE ROWNUM <= 20          -- 上界写在内层
) WHERE rn >= 11;              -- 下界写在外层
```

记忆口诀：**上界在内，下界在外**。

### 7.4 空字符串就是 NULL

MySQL 里 `''` 和 `NULL` 是两回事，Oracle 里 **`''` 会被当成 `NULL`**：

```sql
UPDATE users SET email = '' WHERE user_id = 1;
-- 实际效果等价于 SET email = NULL！

SELECT * FROM users WHERE email = '';   -- 永远查不到（NULL 比较返回未知）
SELECT * FROM users WHERE email IS NULL; -- 这才是对的
```

从 MySQL 迁移过来的代码里，`WHERE xxx = ''` 这类判断要全部排查一遍。

### 7.5 大小写：数据敏感，标识符不敏感

- **数据**和 MySQL 一样区分大小写：`'alice'` 和 `'ALICE'` 是不同的值
- **标识符**（表名、列名）不区分大小写，但存储时统一转成**大写**。所以数据字典里查 `USERS` 而不是 `users`
- 唯一例外：**双引号**。`CREATE TABLE "my_table"` 会强制保留小写，之后访问必须永远带双引号写 `"my_table"`——一些 ORM 生成的迁移脚本会踩这个坑，见到"表明明存在却查不到"，先怀疑这个

### 思考与练习

1. 用 frank 用户建一张 `addresses`（收货地址）表，包含省/市/详细地址、是否默认，并把某个用户的地址查出来。

### 本章核心总结

- **实例 ≠ 数据库**：实例 = SGA + 后台进程（运行态），数据库 = 磁盘文件（静态）；Oracle Server = 实例 + 数据库；RAC 是多实例开一个库
- **存储四层**：表空间 → 段 → 区 → 块；业务表放 `USERS`，别碰 `SYSTEM`
- **用户就是 schema**：MySQL 的"库" ≈ Oracle 的"用户"；没有 `USE`，访问别人的表写全名
- **语法三板斧**：类型用 `VARCHAR2/NUMBER`；自增用 `IDENTITY`（或序列）；分页 `FETCH`，老代码认得 `ROWNUM`（上界在内，下界在外）
- **两个大坑**：`''` 等于 `NULL`；双引号标识符强制区分大小写
