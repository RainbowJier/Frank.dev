# Frank.dev 项目宪章

## Core Principles

### I. 内容为王

站点价值核心是文章与项目复盘的质量。任何功能性改动（主题、构建、交互）都必须服务于阅读体验，不为炫技加功能；一篇文章的发布标准是"三个月后自己还愿意重读"。

### II. 静态站点的边界（不可妥协）

无后端、无数据库、无服务端逻辑：一切交互在客户端实现，一切动态数据在构建期生成。涉及 API key 等敏感信息一律走构建期注入（GitHub Secrets），明文密钥永远不进仓库——2026-08 的 key 盗刷事故是本条的由来。

### III. 产物不入库

`public/`、`db.json`、`.deploy_git/` 都是生成产物，已 gitignore，任何情况下不提交。仓库里只应有源文件（Markdown、模板、样式、脚本、配置）。

### IV. 本地验证先于推送（不可妥协）

push main 即触发线上部署，没有 staging 环境，main 就是生产。因此任何改动推送前必须完成：`pnpm build` 零错误 + `pnpm server` 本地预览确认视觉效果 + 用户确认。禁止"先推上去看效果"。

### V. 主题定制可追溯

`themes/oranges/` 是本地化定制版（MIT）。修改保持小而集中，每处定制在提交信息中说明动机；不盲目跟随上游主题升级，升级前先评估定制 diff 的合并成本。

### VI. 简单性（YAGNI）

个人站点，单维护者：不引入 CI 之外的工具链、不加测试框架（以本地验证 + 构建成功为门禁）、不做多环境配置。能用 Markdown + 模板解决的，不写代码。

## 开发工作流

功能性改动走 spec-kit 流程（specify → plan → tasks → implement，见 AGENTS.md）；日常写作直接操作。两类工作都以 conventional commits + 中文描述提交。

## Governance

本宪章高于项目内其他惯例文档；与 AGENTS.md 冲突时以本宪章为准。修订必须更新版本号并在提交信息中说明动机。
