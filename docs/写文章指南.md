# 📝 写文章指南（Hexo 版）

给 Frank's Notes 写一篇新文章。站点是 Hexo + 中英双构建，写完 `git push` 到 `main` 自动上线。

> **核心约定**：文章是 Markdown + front-matter。中文放 `source/_posts/`，英文放 `source_en/_posts/`（同名文件）。
> **新文章只需要写中文**；英文不写时，英文站（`/en/`）就少这一篇，不会报错，可以后补。

---

## 第 1 步：写中文文章

在 `source/_posts/` 新建一个 `.md` 文件，文件名用英文标识（会成为 URL）：

```bash
# 例如：source/_posts/mybatis-tips.md
```

文件开头是 front-matter（两行 `---` 之间），下面是 Markdown 正文：

```markdown
---
title: MyBatis-Plus 踩坑记录
date: 2026-08-20 14:00:00
categories:
  - 技术
tags:
  - MyBatis-Plus
  - Java
description: 记录使用 MyBatis-Plus 时踩过的几个坑与解法。
---

很多人用 MyBatis-Plus ……（正文第一段）

## 第一个坑：条件构造器

正文段落，直接写 Markdown 即可。

- 列表项一
- 列表项二

> 一句值得强调的话（引用块）。

\`\`\`java
// 代码块照常写
QueryWrapper<User> w = new QueryWrapper<>();
\`\`\`
```

**要点**：
- `title` / `date` 必填；`categories` 决定分类页（旧的随笔/技术筛选标签现在就是分类）。
- `description` 会作为摘要和 SEO 描述。
- 想手控摘要：在正文里加一行 `<!-- more -->`，其上为摘要。

## 第 2 步（可选）：写英文版

在 `source_en/_posts/` 建**同名**文件 `mybatis-tips.md`，front-matter 用英文分类（如 `Tech`）、正文写英文。两套独立，互不影响。

不写英文也完全没问题——英文站只是少这一篇。

## 第 3 步：预览

```bash
npm run server          # 中文：http://localhost:4000
# 或构建出静态文件再预览：
npm run build && npx serve public   # 同时看 / 和 /en/
```

## 第 4 步：发布

```bash
git add -A
git commit -m "post: 新文章 MyBatis-Plus 踩坑记录"
git push
```

push 到 `main` 后，GitHub Actions 自动构建中英两套并发布到 https://frank-dev.site ，约 1 分钟生效。

> 首页「最新文章」、`/archives/`、`/categories/`、`/tags/`、搜索索引、RSS **全部由 Hexo 自动生成**，无需手动维护任何列表。

## front-matter 速查

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 文章标题 |
| `date` | ✅ | 发布时间，影响排序与归档（`YYYY-MM-DD HH:MM:SS`） |
| `categories` | 推荐 | 分类，旧的随笔/技术筛选就是它 |
| `tags` | 可选 | 标签 |
| `description` | 可选 | 摘要 / SEO |
| `cover` | 可选 | 封面图 URL |
| `updated` | 可选 | 更新时间（不填用 date） |
| `series` / `series_order` | 可选 | 系列文章分组与排序 |

## 常见问题

**Q：想放图片？**
A：放 `source/images/`（中文）/ `source_en/images/`（英文），正文用 `![说明](/images/xxx.png)` 引用（路径以 `/` 开头，根随语言自动变 `/` 或 `/en/`）。

**Q：分类/标签是新建的，要额外配置吗？**
A：不用。Hexo 自动扫描 `categories` / `tags` 生成对应页面。首页菜单的「分类 / 标签」已就绪。

**Q：想让文章出现在首页「最新文章」？**
A：自动的——首页取最新的 2 篇，按 `date` 倒序。

**Q：旧版（HTML + i18n 字典）怎么回？**
A：旧流程已废弃。迁移前的纯静态版本保留在 git 历史，回滚需 checkout 历史提交。
